# 战略解码与目标落地

## 适用场景

优先处理这类问题：

- 帮我把战略目标拆开
- 公司战略怎么落到团队
- 年度目标怎么拆到部门和岗位
- 为什么战略有了但执行很差
- 怎么做关键项目推进
- 怎么做战略落地的监控和复盘

## 核心定位

这个 Skill 不负责重新做完整战略研究。

它专门解决一件事：

把已经相对明确的战略方向，翻译成团队能执行、管理层能检查、老板能追结果的一套执行系统。

## 核心原则

1. 战略不解码，就只存在于老板脑子里。
2. 目标必须能一路拆到团队、部门、岗位和个人动作。
3. 只有结果目标不够，还必须有关键项目、关键节点和关键动作。
4. 执行差，通常不只是人不行，也可能是目标空、责任虚、机制弱。
5. 每次输出都要回答：谁负责、何时完成、怎么检查、偏了怎么办。

## 先判断问题卡在哪

收到任务后，先判断更像哪一类问题：

- A. 战略目标本身太空
- B. 中层没有吃透战略
- C. 没拆到关键项目和岗位
- D. 执行节奏和监控机制缺失
- E. 人在做事，但关键控制点没人盯

不要一上来就写 OKR/KPI 表。

先判断问题属于“目标问题、组织问题、项目问题、管理问题、机制问题”中的哪几类。

## 标准工作流

### 1. 明确上层目标

至少确认：

- 这是公司级、业务级，还是项目级目标
- 时间周期是年度、季度，还是专项战役
- 最终要达成的结果是什么
- 当前最重要的 1-3 个战略重点是什么

如果上层目标本身模糊，先帮助用户重写目标，再往下拆。

### 2. 识别关键控制点

先找决定胜负的关键点，而不是平均分配任务。

优先识别：

- 关键用户
- 关键产品节点
- 关键增长节点
- 关键营收节点
- 关键组织节点
- 关键资源投入点

一句话标准：

如果这个点失控，整体目标大概率达不成，那它就是控制点。

### 3. 做战略解码

默认按这条链路往下拆：

公司战略 -> 业务目标 -> 团队目标 -> 部门目标 -> 岗位目标 -> 个人动作

拆解时至少回答：

- 这一层承担什么结果
- 为结果负责的对象是谁
- 关键动作有哪些
- 节点怎么排
- 需要哪些协同

### 4. 形成关键项目清单

目标落地，最终要落到关键项目。

每个关键项目至少写清：

- 项目名称
- 项目目标
- 负责人
- 关键节点
- 衡量指标
- 风险点

### 5. 设计执行节奏

默认给出三层节奏：

- 周节奏：跟进动作和节点
- 月节奏：检查结果和偏差
- 季度节奏：复盘方向和资源配置

如果任务是年度目标，必须补充季度节奏。

### 6. 设计监控与预警

不要只给结果指标，也要给过程指标。

至少包含：

- 结果指标
- 过程指标
- 预警阈值
- 偏差后的修正动作

### 7. 设计复盘机制

复盘不只是看有没有完成。

至少复盘：

- 目标设定是否合理
- 控制点是否抓对
- 项目推进是否卡在协同
- 负责人是否具备胜任力
- 下阶段该收缩、加码还是调整

## 推荐输出结构

```markdown
## 一、当前问题判断
- 目标问题
- 项目问题
- 组织问题
- 机制问题

## 二、战略解码
- 公司/业务目标
- 团队目标
- 部门目标
- 岗位目标

## 三、关键项目清单
| 项目 | 目标 | 负责人 | 关键节点 | 指标 |
|---|---|---|---|---|

## 四、执行节奏
- 周节奏
- 月节奏
- 季度节奏

## 五、监控与预警
- 核心指标
- 预警信号
- 修正动作

## 六、下一步动作
- 先做什么
- 谁先动
- 一周内完成什么
```

## 高质量输出标准

- 不是只写“目标”，而是写“结果 + 动作 + 负责人 + 节点”
- 不是只写“执行”，而是写“监控 + 预警 + 复盘”
- 不是平均拆解，而是围绕控制点拆解
- 不是把所有事都列出来，而是只抓关键战役和关键项目

## 常见错误

- 上层目标还没清楚，就开始拆表
- 把所有部门都写得一样重要
- 只有 KPI，没有关键动作
- 只有负责人，没有协同关系
- 只有周报动作，没有季度复盘

## 协同关系

- 需要重新判断方向和机会点时，联动 `战略研究`
- 需要组织调整或人才配置时，联动 `战略驱动的组织与人才设计`
- 需要把目标继续翻译到产品、品牌、增长动作时，联动 `战略驱动的产品、品牌与增长`
