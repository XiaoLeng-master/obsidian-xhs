# 战略驱动的产品、品牌与增长

## 适用场景

优先处理这类问题：

- 战略定了，产品该怎么定义
- 从战略推导产品路线图
- 从战略推导品牌定义和营销打法
- 从战略推导用户增长和营收增长
- 新方向如何做产品、品牌和增长联动
- 怎么把产品、品牌、增长放在一套逻辑里

## 核心定位

这个 Skill 处理的是“战略到市场”的那一段。

核心任务是把战略翻译成：

- 产品定义
- 品牌定义
- 营销策略
- 增长路径
- 营收模型

## 核心原则

1. 产品、品牌、增长都要回到同一个用户价值。
2. 产品定义不能脱离用户场景和竞争环境。
3. 品牌不是单独做宣传，而是用户对产品价值的认知。
4. 增长不是单独拉新，而是拉新、激活、留存、付费、传播的系统。
5. 营销点优先来自产品核心功能点和核心价值点。
6. 方案必须给取舍，不要“产品也做、品牌也做、渠道也全做”。

## 标准工作流

### 1. 先明确战略约束

至少确认：

- 这次服务的目标用户是谁
- 当前最重要的业务目标是什么
- 当前阶段是从 0 到 1，还是从 1 到 10
- 主要竞争对象是谁
- 当前资源主要受限在哪里

### 2. 做产品定义

默认从 4 个问题开始：

- 用户是谁
- 用户在什么场景下有强需求
- 我们提供什么核心价值
- 为什么用户要选我们而不是别人

然后继续补：

- 核心功能
- 辅助功能
- 核心流程
- 当前阶段先做什么，不做什么
- 产品如何外扩

如果产品方案不能说明“核心功能 + 核心流程”，通常还没定义清楚。

### 3. 做产品路线

根据战略和阶段，把产品拆成：

- MVP
- 第一阶段强化
- 第二阶段外扩

每一阶段至少写清：

- 目标
- 功能重点
- 关键指标
- 验证方式

### 4. 做品牌定义

品牌定义至少综合两层：

- 官方希望表达的价值
- 用户真实认同的价值点

最后形成一版用户能理解、能传播、能记住的品牌口径。

默认提醒：

- 对互联网产品来说，产品本身就是品牌的重要组成部分
- 产品内传播往往比产品外传播更重要

### 5. 做营销策略

默认从这几块来设计：

- 核心营销点
- 内容主题
- 渠道组合
- 物料类型
- 分发方式

优先回答：

- 用户在哪里
- 用户会被什么价值点打动
- 用什么内容和形式最容易触达

### 6. 做增长模型

默认先用 AARRR 拆：

- Acquisition 拉新
- Activation 激活
- Retention 留存
- Revenue 付费
- Referral 传播

如果是 SaaS 或协作类产品，额外检查是否适合 PLG：

- 是否边际成本低
- 是否上手快
- 是否能先用后买
- 是否有传播/邀请机制
- 是否可以设计自助转化

### 7. 做营收模型

至少检查：

- 收费对象
- 收费方式
- SKU 梯度
- 转化路径
- 升级路径
- 续费与增购路径

如果增长方案只讲用户数，不讲付费和营收，这套方案是不完整的。

## 推荐输出结构

```markdown
## 一、战略到市场的核心判断
- 服务谁
- 解决什么
- 靠什么赢

## 二、产品定义
- 用户与场景
- 核心价值
- 核心功能
- 核心流程

## 三、产品路线
- MVP
- 第一阶段
- 第二阶段

## 四、品牌定义
- 官方价值
- 用户认同价值点
- 最终品牌口径

## 五、营销策略
- 核心营销点
- 内容主题
- 渠道与分发

## 六、增长路径
- AARRR / PLG
- 北极星指标
- 关键实验

## 七、营收模型
- 收费设计
- 转化设计
- 增购续费设计
```

## 高质量输出标准

- 产品、品牌、增长围绕同一批目标用户
- 明确核心价值，而不是功能堆砌
- 渠道选择有取舍，不是全渠道平推
- 增长指标与业务目标连得上
- 营收设计与产品阶段匹配

## 常见错误

- 一上来先讨论功能，不先定义用户和价值
- 把品牌当成单独宣传部门的事
- 只讲拉新，不讲激活、留存和付费
- 只讲增长，不讲产品核心价值
- 只讲用户数，不讲营收路径

## 协同关系

- 需要先做上层机会点和战略判断时，联动 `战略研究`
- 需要把结果进一步拆到团队和执行机制时，联动 `战略解码与目标落地`
- 需要把战略翻译成组织、招聘和培养动作时，联动 `战略驱动的组织与人才设计`
- 需要细化需求、产品化落地和正式方案时，优先联动：
  - `用户调研-需求抓取-产品化落地`
  - `通用（产品策划 PRD）`
  - `通用（产品逻辑梳理）`
