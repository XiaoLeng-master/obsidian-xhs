# AI编程做产品——需求与设计篇

> 方向选对了后面都顺，选错了怎么努力都白搭。找需求不是拍脑袋，是用排除法筛出来的。

---

## 一、选需求——三个必须同时满足的标准

| 标准 | 判断方法 | 不满足的后果 |
|------|---------|-------------|
| **功能单一** | 一个产品只解决一个问题，一句话说清用户什么时候打开它 | 用户搞不清你干嘛的，搜索排名也上不去 |
| **场景清晰** | 能一句话描述用户在什么场景下会用 | 你自己都描述不清，说明方向还不够具体 |
| **没有头部产品** | 搜索结果里现有产品做得不好或根本没有 | 大厂做了好多年的品类，你根本打不过 |

**反面案例：** 做"记账"——需求大，但随手记、鲨鱼记账做了好多年，用户千万级。但"打牌记账"就不一样——场景具体、大厂不会做、打牌的人每次都需要。

**需求大 ≠ 你能做，关键看有没有还没被好好服务的细分角落。**

## 二、4种找需求的方法

### 方法1：小红书评论区挖掘

**操作：** 刷小红书时多看评论区——用户在反复问什么？"求分享""有没有工具能帮我…""怎么搜到的""有链接吗"

**判断信号：**
- 评论区一堆人追着要链接 → 需求真实且强烈
- 博主展示了某个工具但没有卖 → 市场空白
- 同类评论在多个帖子下反复出现 → 需求稳定

**案例：** 博主用Gemini做了一个AI词典，评论区大量"求分享""很需要""能不能卖"——这就是未被满足的需求。

### 方法2：微信搜索验证

**操作：** 打开微信搜"检测""换算""查询"等关键词，看出来的小程序做得怎么样。

**判断标准：**
- 有产品但做得很烂（界面丑、广告多、操作不顺）→ **机会！做一个体验更好的版本**
- 有产品而且做得不错 → 换方向
- 搜不到像样的产品 → 需求可能太小，或者是蓝海

**关键认知：** 很多产品做得很烂但依然有几千几万人在用——说明需求是真的，用户忍着难用也要用。

### 方法3：跨平台需求验证

**操作：** 淘宝/闲鱼搜同类虚拟产品，看有没有人在卖。

- 有人在卖且有销量 → 说明有人愿意为这个问题付费
- 没人卖 → 可能没需求，也可能是蓝海，需要结合其他信号判断

### 方法4：自身经历反推

**问自己三个问题：**
1. 过去半年你为什么问题花过钱或花过时间？
2. 你亲手解决过这个问题吗？（自己走过的路才能带人走）
3. 这个问题的"痛感"能让人掏钱吗？（痒点做不出客单）

## 三、需求验证一句话公式

> **"[谁]在[什么场景]下需要[什么功能]，愿意付[多少钱]"**

**示例：**
- "小红书博主在写笔记时需要AI帮生成3个爆款标题，愿意付9.9元/月"
- "宝妈在带孩子逛博物馆时需要讲解音频，愿意付29.9元/馆"
- "打牌的人在结束后需要快速算账，愿意看广告换免费使用"

写不出这句话，就还没找到真需求。

## 四、需求方向速查表

这些是已验证有真实需求的方向类型，供参考：

| 方向类型 | 示例 | 特点 |
|---------|------|------|
| **生活小工具** | 手电筒、噪音检测、保质期计算、亲戚计算器 | 功能极简，大厂看不上，用户量不小 |
| **垂直刷题** | 黄委会刷题、政府会计知识点、考证题库 | 考试人群极精准，付费意愿强 |
| **亲子教育** | 博物馆讲解、儿童认字、绘本阅读 | 家长舍得花钱，内容可持续积累 |
| **创作辅助** | AI标题生成、图片转换、文案改写 | 创作者群体大，使用频次高 |
| **效率工具** | 批量数据提取、自动化流程、格式转换 | 解决重复劳动，用户粘性强 |

**共同点：专注解决一个高频小问题，场景真实、功能不复杂、大厂不会做。**

## 五、写PRD——把想法变成AI能执行的指令

### 什么是PRD

PRD（产品需求文档）就是把你脑子里的想法变成AI能执行的指令。听起来很专业，其实就是写清楚"做什么、给谁用、怎么用、怎么赚钱"。

**你不需要自己写PRD，让AI帮你写。**

### 给AI的PRD生成提示词

```
我想做一个微信小程序/网页工具/Chrome插件，
目标用户是[谁]，
核心功能是[什么]，
用户打开后的操作流程是[1→2→3]，
商业模式是[怎么收费]。
请帮我写一份产品需求文档，包括：
功能列表、页面结构、用户流程图、技术方案建议。
```

### PRD关键原则

| 原则 | 说明 | 为什么 |
|------|------|--------|
| **页面不超过3个** | 第一版控制在3个页面以内 | 页面越少，开发越快，验证越早 |
| **核心功能不超过3个** | 只留最核心的，删掉所有"锦上添花" | 功能越少，越容易做好 |
| **目标是"能用"** | 第一版不追求完美，能走完核心流程就行 | 完美是迭代出来的，不是设计出来的 |

**AI帮你输出PRD后，你要做的只有一件事：读完之后删掉所有"锦上添花"的功能，只留最核心的那一个。**

## 六、出原型——让AI画出产品长什么样

### 两种路径

| 路径 | 操作 | 适合谁 |
|------|------|--------|
| **快速路** | 让AI生成每个页面的界面描述和布局草图（文字+结构） | 想快速推进 |
| **可视路** | 让AI生成HTML原型页面，在浏览器里看效果 | 想看到实际界面 |

### 原型阶段的核心

**不追求好看，追求"流程跑通"。**

用户从 打开→使用→得到结果→付费/看广告，这条路径在原型里走一遍没有断点，就够了。

### 最重要的验证动作

把原型发给3-5个目标用户，只问一个问题：

> **"你愿意为这个功能付钱吗？"**

不用问好不好看、喜不喜欢——只问掏不掏钱。愿意掏钱的需求才是真需求。

## 七、需求阶段常见错误

| 错误 | 正确做法 |
|------|---------|
| 花三天纠结"做什么方向好" | 半天筛出一个方向，做出来验证比想清楚更重要 |
| 上来就想做"全家桶" | 一个产品只解决一个问题 |
| 需求大就冲进去 | 需求大≠你能做，关键看有没有头部竞品 |
| 自己觉得很好就开始做 | 找3-5个目标用户问"你愿意付钱吗" |
| PRD写得很完整很详细 | 第一版PRD越简单越好，3个页面3个功能封顶 |
| 原型追求好看 | 原型只追求流程跑通，好看是迭代以后的事 |
