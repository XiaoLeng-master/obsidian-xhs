# RAG 知识库构建技术全景

> 来源：大淘宝技术架构部。深入探讨构建高质量 RAG 知识库的垂直技术原理与工程实践。

---

## 核心要点

### RAG 评估框架（RAGAS）

| 维度 | 评估内容 |
|------|---------|
| 检索相关性 | 召回的文档是否与查询相关 |
| 生成忠实度 | 生成的答案是否忠实于检索到的文档 |
| 答案相关性 | 生成的答案是否回答了用户的问题 |

### 文档切分策略

| 策略 | 适用场景 |
|------|---------|
| Late Chunking | 先做完整文档 embedding，再做切分 |
| 意图驱动切分 | 按语义边界切分，而非固定长度 |

### 检索范式对比

| 类型 | 代表 | 特点 |
|------|------|------|
| 稀疏检索 | BM25 | 关键词匹配，精确但语义弱 |
| 稠密检索 | DPR | 语义匹配，泛化好但计算贵 |
| 混合检索 | BM25 + Dense | 取两者之长 |

### 查询增强

- **HyDE**：先让 LLM 生成假设答案，用假设答案做检索（比原始 query 更精准）
- **Query Rewriting**：LLM 改写模糊 query 为精确检索语句

### 重排序

- **Cross-Encoder Reranker**：对 Top-K 候选做精细相关性打分，牺牲一点延迟换精度

### 前沿架构

- **AutoRAG**：自动化 RAG 超参数优化
- **QuIM-RAG**：问题倒排索引，先建问题→文档映射
- **OpenViking**：文件系统范式的知识库

### RAG vs Long Context 选型

| 条件 | 方案 |
|------|------|
| 数据 < 50K tokens，更新频率低 | Long Context |
| 数据量大、更新频繁、需精确召回 | RAG |
| 两者兼顾 | RAG 粗筛 + Long Context 精读 |
