# 横纵分析法

> 参考卡兹克 @KKKKhazix 的 hv-analysis 方法。
> 核心理念：纵向追时间深度，横向追同期广度，最终交汇出判断。

---

## 方法概述

横纵分析法是一种结构化的深度研究方法。当你面对一个新领域、新产品、新概念时，不要零散地搜索，而是按横纵两个维度系统性地展开。

---

## 纵向：时间深度（追历史）

回答「这个东西从哪来的？」

### 调研框架

| 问题 | 要找什么 |
|------|---------|
| 起源 | 这个东西最早是谁在什么背景下做出来的？ |
| 关键转折 | 经历了哪些重要变化？（融资、功能迭代、竞品出现、政策变化） |
| 发展阶段 | 现在处于什么阶段？（萌芽/爆发/成熟/衰退） |
| 失败记录 | 有没有人做过类似的事但失败了？为什么失败？ |
| 未来趋势 | 接下来 1~3 年可能会怎么发展？ |

### 信息源推荐
- 36氪/虎嗅/ TechCrunch 的历史报道
- 相关公司的融资记录和里程碑
- Google Trends 搜索趋势
- 行业报告（艾瑞、易观等）
- 知乎/Reddit 上的行业讨论

---

## 横向：空间广度（找竞品）

回答「同期有哪些东西？他们在做什么？」

### 调研框架

| 问题 | 要找什么 |
|------|---------|
| 直接竞品 | 谁在做一模一样的事情？ |
| 间接竞品 | 谁在用不同的方式解决同一个问题？ |
| 替代方案 | 用户现在没有这个产品时，用什么东西代替？ |
| 差异化空间 | 竞品没有做好的地方是什么？用户抱怨最多的是什么？ |
| 市场格局 | 谁在领跑？谁在追赶？有没有巨头盯上？ |

### 竞品对比维度

| 维度 | 竞品A | 竞品B | 竞品C |
|------|-------|-------|-------|
| 目标用户 | | | |
| 核心功能 | | | |
| 定价 | | | |
| 优势 | | | |
| 劣势/用户吐槽 | | | |
| 技术栈（专业模式） | | | |
| 团队规模 | | | |
| 融资情况 | | | |

---

## 交汇：判断

回答「我该怎么做？」

### 判断框架

| 问题 | 分析 |
|------|------|
| **我的切入机会在哪？** | 竞品没做好的 × 我擅长的 × 有需求的 → 交叉点 |
| **主要风险是什么？** | 技术风险？市场风险？政策风险？团队风险？ |
| **最小可行方案是什么？** | 砍掉一切非核心功能后，剩下的那个功能是什么？ |
| **第一波用户在哪？** | 从哪个渠道能找到愿意试用的第一批人？ |
| **如果这个想法错了，最早怎么发现？** | 设置什么指标来判断「该放弃了」？ |
