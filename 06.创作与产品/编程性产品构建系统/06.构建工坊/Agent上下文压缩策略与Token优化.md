> **一句话**：六大主流 Agent 有六种不同的压缩哲学。共识是：分层渐进、成本递增、增量摘要优于全量摘要、用户消息有特权、近端保护、单调边界。

---

## 六大 Agent 压缩哲学对比

| Agent | 压缩策略 | 特点 |
|-------|---------|------|
| **Claude Code** | 五段流水线，成本递增 | 从本地操作到 LLM 摘要兜底 |
| **Codex CLI** | 优先保护近期用户消息 | 其余替换为 handoff 摘要 |
| **OpenCode** | 时间戳标记 | 可逆隐藏（可恢复） |
| **MemGPT** | OS 级内存调度 | 上下文 = RAM，历史 = 磁盘 |

> 没有最优解，只有取舍。

---

## 六大共识原则

1. **分层渐进**，不一刀切
2. **成本严格递增**——便宜的（本地操作）先做，LLM 摘要最后兜底
3. **增量摘要优于全量摘要**
4. **用户消息有特权**——一字不动
5. **保护近端**——最近几轮不压缩
6. **单调边界**——绝不滑窗（一旦标记，永不变）

---

## Claude Code 的滑窗陷阱

如果每步都重算 stub 边界，每完成一个 step 就有旧结果滑出窗口：

- 导致每一步都触发 `cache_write`（单价是 `cache_read` 的 **12.5 倍**）
- 一个 177 step 的会话，**83% 的成本都是 cache_write**

> **核心原则：stub 决策必须单调推进，一旦标记永不变。**

---

## 四级水位线（参考方案）

| 水位 | 阈值 | 动作 | 成本 |
|------|------|------|------|
| Tier 0 | ≤ 60% | 不做 | 零 |
| Tier 1 | 60-80% | 纯字符串处理 | 零 |
| Tier 2 | 80-95% | 替换为占位符 | 零 |
| Tier 3 | ≥ 95% | LLM 增量摘要兜底 | 高 |

> 用真实 token（LLM 返回的 `usage.totalTokens`）做触发判断，不靠 `text.length/3` 估算（中英混合误差 30-50%）。

## Token 优化速查

| 策略 | 效果 |
|------|------|
| **缓存复用** > 频繁重开 | 同一会话后续每轮 1/10 费用 |
| **确定任务用 Hooks**，不写规则 | 100% 生效 vs 70% 遵循率 |
| **Skill 不过载** | 只装项目需要的，避免稀释上下文预算 |
| **子 Agent 节制使用** | 只在"独立互不干扰的耗时任务"时用 |
| **规则文件精简** | 200 行以内遵循率 92%，超 400 行降至 70% |

## 多 Agent 工作额度榨取技巧

### 5h + 7d 两层滚动额度

- 第一层：5 小时窗口，从首次使用开始计时（非整点重置）
- 第二层：7 天周限，滚动计时

### 双引擎策略

```
一个 $100 Claude Code 做工程执行
一个 $100 Codex 做验证和复杂逻辑
> 一个 $200 的资源
```

一个写一个审，左右互搏，同时避免单点故障。

### 非交互模式 + 定时调度

```bash
claude -p "任务描述"    # 走订阅额度，非 API 计费
codex exec "任务描述"
```

- 深夜用 shell 循环批量跑任务
- `/goal` 模式：设定目标和验收标准后 AI 自驱迭代
- `/loop` 模式：定时间隔检查，额度重置后继续
