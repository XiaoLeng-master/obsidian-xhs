> **一句话**：CLAUDE.md 是配置，不是文档。200 行是注意力黄金线。规则越短越听话，路径范围规则是最佳实践，三种无效内容要定期清理。

---

## CLAUDE.md 的本质

| README | CLAUDE.md |
|--------|-----------|
| 给人看的 | 给 Agent 看的 |
| 描述项目 | 定义行为规则 |
| 什么时候看都行 | **每次对话开始时自动加载** |
| 可以很长 | 必须精简 |

> CLAUDE.md 是所有后续交互的"基本事实"。它不是文档，是配置。

---

## 200 行黄金线

来自 SFEIR Institute 的实证数据：

| 规则文件行数 | 遵循率 |
|------------|--------|
| ~200 行（单文件） | 92% |
| > 400 行（单文件） | ~70% |
| 拆分为多个 30 行模块文件 | **96%** |

**Less is More。能精准描述就不泛泛而谈，能按需加载就不全量堆砌。**

---

## 路径范围规则（最佳实践）

使用 `.claude/rules/*.md` 中的 YAML frontmatter：

```yaml
---
paths: ["src/api/**/*.ts"]
---
```

**规则仅在 Agent 处理匹配文件时按需加载**——节省 token + 减少上下文噪声。

## 三类无效内容（定期清理）

| 类型 | 例子 | 处理 |
|------|------|------|
| **重复型** | 复制架构文档到 CLAUDE.md | 删除，用引用链接 |
| **愿望型** | "希望测试覆盖率达到 90%" | 删除，无法验证的规则无效 |
| **词汇表型** | 解释常见术语 | 移到独立 reference 文件 |

## 六部分模板（总量控制在 50 行起）

```markdown
1. 项目概览 (5行)
2. 常用命令 (10行)
3. 架构约定 (10行)
4. 编码规范 (10行)
5. 硬约束 (5行)
6. 已知陷阱 (10行)
```

**预留增长空间，初始 50 行。当 Claude 犯同样的错误两次以上，加一条新的防御规则。**

## 配套 Token 优化原则

### 缓存复用 > 频繁重开

主流模型有提示缓存机制。同一会话内之前发过的内容被缓存，后续每轮只需付 1/10 费用。

> **切换任务时压缩历史比新开对话划算。**

### 确定性任务交给 Hooks

代码格式化、危险命令拦截、提交前跑测试 → 用**确定性自动化脚本**（Claude Code Hooks），不要写到规则文件里。

> **规则文件本质上是建议，不是 100% 生效的禁令。**

### Skill/MCP 不要过载

Claude Code 的 Skill 描述有上下文预算上限。装过多会导致低频 Skill 无法触发。**项目专属 Skill 放项目目录，不全局装。**

---

## 维护节奏

| 频率 | 动作 |
|------|------|
| 每次 Claude 犯重复错误 | 加一条防御规则 |
| 每 3-6 个月 | 审查清理（3 个月前为弥补模型弱点写的规则可能变成新枷锁） |
| 每次模型大版本升级 | 重新审查所有规则的必要性 |

> "模型在进化，3 个月前为了弥补模型弱点写的规则，可能变成新模型的枷锁。"
