# 数据库设计模板

> 专业模式专用。用于设计关系型数据库的表结构。

---

## 设计原则

1. **先画 ER 图，再建表** — 理清实体关系比写 SQL 更重要
2. **宁多不少** — MVP 阶段不要过度设计，但字段可以多预留
3. **索引跟着查询走** — 不要提前建一堆索引，等查询变慢再加
4. **软删除优于硬删除** — 用 `deleted_at` 字段，数据丢了就回不来了

---

## 模板

```markdown
# [项目名称] 数据库设计

## ER 图

> 用 Mermaid 画：
\```mermaid
erDiagram
    User ||--o{ Post : has
    Post ||--o{ Comment : has
\```

## 表设计

### 表名：users

| 字段 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PRIMARY KEY, AUTO_INCREMENT |
| email | VARCHAR(255) | 邮箱 | UNIQUE, NOT NULL |
| password_hash | VARCHAR(255) | 密码哈希 | NOT NULL |
| nickname | VARCHAR(100) | 昵称 | |
| avatar_url | VARCHAR(500) | 头像URL | |
| created_at | TIMESTAMP | 创建时间 | NOT NULL, DEFAULT NOW() |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL, DEFAULT NOW() |
| deleted_at | TIMESTAMP | 删除时间 | 软删除字段 |

## 索引设计

| 索引名 | 字段 | 类型 | 用途 |
|--------|------|------|------|
| idx_users_email | email | UNIQUE | 登录查询 |
| idx_users_created_at | created_at | BTREE | 按时间排序查询 |

## 常用字段命名约定

| 用途 | 字段名 | 类型 |
|------|--------|------|
| 主键 | `id` | BIGINT |
| 外键 | `[table]_id` | BIGINT |
| 创建时间 | `created_at` | TIMESTAMP |
| 更新时间 | `updated_at` | TIMESTAMP |
| 软删除 | `deleted_at` | TIMESTAMP (nullable) |
| 状态 | `status` | TINYINT 或 VARCHAR |
| 排序 | `sort_order` | INT |
