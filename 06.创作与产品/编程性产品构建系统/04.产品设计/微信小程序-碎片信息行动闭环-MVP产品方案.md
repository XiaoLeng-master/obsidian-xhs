# 「信息→行动」MVP 产品方案

## 一句话描述
> 微信生态内的碎片信息消化工具——转发即收藏，AI 自动摘要 + 生成待办，把"存了"变成"做了"。

## 目标用户
- **核心用户**：25-40 岁职场人，微信重度用户，每天转发大量信息到文件助手但从不回看
- **次要用户**：内容创作者、自学者、需要持续输入信息的知识工作者

## 核心问题
- 用户看到一篇可能有用的文章 → 转发到微信文件助手 → 永远不打开
- 痛点程度：**9/10**（用户自己验证了：每天发生，但缺乏解决方法）
- 现有方案：微信文件助手（无AI）/ 腾讯IMA（需手动整理，无待办）/ 话袋（在链路末端）/ flomo Cubox（需跳出微信）

## 解决方案
- **把微信转发这个 0.5 秒的动作变成信息消化的入口**
- 优势：用户不需要养成新习惯——转发这个动作本来就每天在做，我们只是把目的地从"文件助手"换成"有 AI 帮你处理"
- 核心差异化：**信息入口优势**——竞品在链路末端等用户"决定整理"，我们在链路前端"帮用户整理"

## 核心功能（MVP）

1. **转发收藏**：用户在微信里转发文章/截图/链接到小程序，0.5 秒完成收藏
2. **AI 摘要**：AI 自动提取标题、核心观点、关键数据，帮用户判断是否值得深读
3. **待办生成**：AI 从信息中生成具体行动项——"今晚花 10 分钟读完""周五试用文中提到的工具"

> 砍掉了什么？
> - 自动分类标签 → v2（MVP 手动加 1-2 个标签就够了）
> - 定时提醒 → v2（先通过微信服务通知提醒）
> - 打卡/正反馈 → v2（MVP 先验证"存→看→做"闭环是否成立）
> - 知识库检索 → v2（先验证用户会不会持续用）

## 用户流程

1. 用户在微信里刷到一篇文章 → 点右上角「…」→ 转发 → 选择「XXX」小程序
2. 小程序接收 → 3-5 秒 AI 处理 → 显示摘要卡片（标题 + 3 个要点 + 1 个待办）
3. 用户看一眼摘要 → 判断这篇值不值得深读
4. 点开待办列表 → 看到"今晚读这篇""周五试这个工具" → 勾掉做完的
5. 小程序通过微信服务通知提醒未完成的待办 → 用户回来继续

## 商业模式
- **收入来源**：订阅制
- **定价策略**：免费版（每日 3 条）/ Pro 版 ¥9.9/月 或 ¥99/年（无限 + AI 深度分析）
- **盈亏平衡点**：按微信云开发最低成本，约 500 付费用户覆盖服务器和 API 成本

## 关键指标
- **北极星指标**：**每周完成待办数** — 不是"收藏了多少"，是"做了多少"
- **辅助指标**：收藏→摘要查看转化率、7 日留存率

## 竞争定位
- **直接竞品**：腾讯 IMA（微信生态最强）、话袋（智能文件夹）、flomo/Cubox（跨平台）
- **我的差异化**：信息入口优势 + AI 自动处理 + 行动闭环（存→看→做）
- **护城河**：用户收藏的越多，AI 对用户的偏好理解越准，替换成本越高

## 风险与假设
- **最大假设**：用户愿意把"转发目的地"从文件助手改成一个小程序。如果用户转发的习惯改不了，产品就没人用 → 用微信"聊天工具栏"快捷入口降低切换成本
- **最大风险**：腾讯 IMA 随时可能加 AI 自动处理功能 → 必须跑得比它快
- **最小成本验证**：先做一个只有"转发→AI 摘要"的极简版，给 10 个朋友试用一周

## 时间线
- **MVP 发布时间**：2 周内
- **第一批用户**：微信好友 10-20 人内测
- **关键里程碑**：10 个用户连续用 7 天 → 证明"存→看→做"闭环成立
