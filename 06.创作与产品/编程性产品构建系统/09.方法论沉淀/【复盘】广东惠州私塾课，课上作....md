【复盘】广东惠州私塾课，课上作业战果：课没上完已完成4000+的课程预售

大家好，我是圆乐。

MVP：先收钱，再做课

6月12日，广东惠州，参加《》的课程，下午讲到MVP（最小可行性产品）时，洋哥给了一个四步框架：明确目标 → 定义指标 → 设计实验 → 迭代优化。

并且反复强调：系统开发永远后置，先验证需求；一次MVP只验证一个假设。

我想验证的假设是：医疗器械企业中高管，是否愿意为我总结的"AI降本增效实战方法论"付费？

1. 明确目标：一次只验一个假设

不要同时验证"课程好不好""价格对不对""交付形式行不行"。我只验证一个：这个人群，这个痛点，愿不愿意掏钱。

2. 定义指标：给自己设生死线

指标	含义	
5人付款	生死线。达到即证明需求存在，值得开干	
10人付款	启动线。值得认真补大纲、设计正式课程	
50人付款	放大线。证明模式成立，可以持续投入	

3. 设计实验：最小成本，系统开发后置

我也用没有产品，靠一段文案进行发售的MVP试验。

现场我蹭别人汇报的时候直接写了一段文案，私域单发（注意：没有发群，没有大规模投放，没有做任何物料）。

文案大意是：2小时讲解+1个月陪伴，几百块钱，验证AI管理降本技巧的课程是否是真需求。

没有海报，没有PPT，没有课程大纲，没有详情页。 就是一段文字，直接问：你愿不愿意为这个买单？

4. 验证结果与迭代

我现场定的目标是至少5人。结果文案发出去，还没轮到我上台分享，群里已经有人响应。上台时，5人付款的目标已经达成。

到了下午上完课，加入人数已经超过20个人，如果按照200元/人算，那么已经完成4000元的预售成果

这意味着需求被验证。接下来的迭代路径是：

现场收款(5人) 
    → 补课程大纲，正式发课 
    → 10人即启动交付 
    → 一阶交付"AI管理降本技巧" 
    → 二阶交付"工具创造工具"（教如何把业务语言变成AI语言，让各岗位自造工具）
```

"失败并不是成功之母，又便宜又快的失败才是成功之母。" 

这段文案的成本几乎为零，但帮我避免了"先花三个月做课，最后发现没人要"的致命错误。
