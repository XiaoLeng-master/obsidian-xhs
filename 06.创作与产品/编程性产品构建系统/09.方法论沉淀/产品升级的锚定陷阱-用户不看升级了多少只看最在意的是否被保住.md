# 产品升级的锚定陷阱：用户不看升级了多少，只看最在意的是否被保住

## 🔬 压缩后的核心命题

**用户评价产品，看的不是「升级了多少」，而是「他最在意的体验有没有被保住」。**

案例：给父亲换了一台性能/屏幕/外观全面升级的新手机，父亲反而差评——因为操作习惯被改变了，而他最在意的就是「和以前一样顺手」。

这与传统产品思维中「更多功能=更好产品」的假设直接矛盾。

## ⚔️ 反驳检查

| 维度 | 检查 |
|------|------|
| 幸存者偏差 | 案例是单一消费品（手机），对软件/AI产品的适用性需验证 |
| 因果倒置 | 无 — 因果链清晰（改变习惯→差评） |
| 边界条件 | 在「用户已深度适应旧版」的场景下成立。全新用户没有锚点，不受此限 |
| 反事实 | 如果能观察到「升级后保留核心操作习惯的产品比大改版的产品留存率高」，命题成立 |
| 知识冲突 | 与产品设计领域公认的「锚定效应」「损失厌恶」一致，不冲突 |

## 🏷️ 价值判定：✅ 高质量

- 一句话说清一个产品原则，简洁有力
- 可迁移到 AI 产品设计：升级 Skill/Agent 时，先确认用户最在意的那个行为路径有没有被破坏
- 局限：单一案例，但核心命题已在行为经济学中被广泛验证

## 💡 可行动作

下次升级自己的产品或 Skill 时，先列出「用户最在意的 3 个核心体验」，确认升级后它们是否原封不动。
