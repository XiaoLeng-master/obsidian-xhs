> **一句话总结**：AI Agent 的核心问题不是能力不够，而是**失忆**和**贪多**。解决方案是三个机制：进度文件（交接本）、功能清单（细粒度拆解）、端到端自测（浏览器自动化验证）。

---

## 问题一：Agent 会失忆

### 根因
Agent 的上下文窗口像一块面积有限的白板。写满了就得擦掉，下一页是全新的空白板。这就像一个轮班制的研发团队，每个新来的工程师都完全不知道上一班做了什么。

### 解决方案：给白板拍照——进度文件

让 Agent 在每次会话结束前，把关键信息写到一个持久化的文件里：

```markdown
# progress.txt

## 已完成
- 搭建了项目脚手架（React + Express）
- 完成了用户登录功能
- 完成了聊天界面的基础布局

## 当前状态
- 正在开发消息发送功能，已完成前端部分，后端API待实现

## 已知问题
- 登录页面在移动端有样式错位

## 下一步
- 完成消息发送的后端API
- 对接WebSocket实现实时推送
```

配合 git commit，下一个 Agent 接手时：
1. 打开 progress.txt，看上一轮做了什么
2. 看 git log，了解最近代码变动
3. 搞清楚状况后，从断点继续

## 问题二：Agent 贪多求全

### 根因
Agent 不知道"完成"长什么样。给它一个模糊大目标（"做一个聊天应用"），它只能自己瞎估计。

### 解决方案：功能清单——拆到可验证的最小单元

```json
{
  "description": "用户点击新建聊天按钮，创建一个空白对话",
  "steps": [
    "打开应用主界面",
    "点击新建聊天按钮",
    "验证新对话被创建",
    "验证聊天区域显示欢迎页面",
    "验证侧边栏出现新对话"
  ],
  "passes": false
}
```

每个功能点都有明确的验证步骤和完成状态。指令变成：**"从功能清单里找到优先级最高、还没通过的功能，只做这一个。"**

一个完整应用可能有数百个这样的功能点。Agent 一次只做一个 → 提交代码 → 更新进度 → 标记完成。下一轮 Agent 来了翻清单找下一个。

> 之前"Agent 提前宣布项目完成"的问题也解决了——功能清单里还有一堆 `passes: false`，完成也得清单说了算。

## 问题三：Agent 从不自测

### 根因
Agent 可能跑了单元测试或用 curl 调了 API，但从未像真正的用户那样在浏览器里端到端操作一遍。

### 解决方案：浏览器自动化 + 先测试再开发

给 Agent 配上浏览器自动化工具，让它像真正的用户一样：
- 打开浏览器
- 访问应用
- 点击按钮
- 输入文字
- 检查页面是否正确渲染

**规矩：每次开始新功能之前，先跑一遍基础功能的端到端测试。** 先测试再开发，发现问题先修，确保地基稳固后再往上建。

---

## 完整的 Agent Harness 工作流

```
1. 打开进度文件，了解项目当前状态
2. 查看 git 记录，了解最近的改动
3. 启动开发服务器
4. 用浏览器跑一遍基础功能测试
   - 如果有 bug，先修 bug
   - 如果一切正常，继续
5. 从功能清单中选择下一个待完成的功能
6. 实现这个功能
7. 用浏览器端到端验证
8. 提交代码，更新进度文件
```

> 这种指挥 AI Agent 的外围系统，就是所谓的 **Agent Harness**。
