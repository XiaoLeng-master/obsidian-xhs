# 发布检查清单

> 每次产品上线前，逐项检查。不凭记忆，靠清单。

---

## 代码质量

- [ ] 所有测试通过
- [ ] 没有遗留的调试代码（console.log、print、临时注释）
- [ ] 敏感信息已移除（API Key、密码、内网地址）
- [ ] 代码已合并到主分支
- [ ] 版本号已更新

## 功能完整性

- [ ] 核心功能可正常使用
- [ ] 边界情况已处理（空数据、网络异常、大文件等）
- [ ] 错误提示对用户友好（不是技术错误堆栈）
- [ ] 新用户首次使用体验流畅（能自己完成核心任务）

## 性能与安全

- [ ] 关键接口响应时间可接受（< 500ms）
- [ ] 数据库查询有索引、无 N+1 问题
- [ ] 输入验证和防注入
- [ ] HTTPS 已配置
- [ ] 备份策略已就位

## 部署

- [ ] 数据库迁移脚本已准备好
- [ ] 环境变量已配置
- [ ] 回滚方案已准备好（万一上线出问题怎么回退）
- [ ] 监控和告警已配置

## 文档与沟通

- [ ] API 文档已更新
- [ ] Changelog 已写好
- [ ] 已知问题已记录（如果有些 bug 来不及修，要写出来）

## 推广准备

- [ ] 落地页 / 产品介绍页已准备好
- [ ] 发布文案已写好
- [ ] 推广渠道已确认（发哪里？什么时候发？）
- [ ] 用户反馈收集渠道已就位

---

## 上线后 24 小时

- [ ] 监控关键指标（错误率、响应时间、用户量）
- [ ] 检查用户反馈渠道
- [ ] 准备热修复能力（如果发现紧急 bug 能快速修）
