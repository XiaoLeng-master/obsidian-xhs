# 飞书文档同步

> 把 vault 笔记一键同步到飞书知识库，格式自动适配，一次到位。

## 核心规则

### 飞书排版适配（必须遵守）

飞书文档和 Obsidian 的换行逻辑不同：

| Obsidian | 飞书 |
|----------|------|
| 单换行 `\n` = 新行 | 单换行 `\n` = **被合并到同一段落** |
| 空行 `\n\n` = 段落分隔 | 空行 `\n\n` = 段落分隔（但间距小） |

**因此必须做以下转换：**

1. **每一句独立成段**：原文中每个单换行都要变成双换行（`\n\n`），让飞书识别为独立段落
2. **段落组之间用零宽字符撑开呼吸感**：在原文的空行位置，插入一个只包含零宽非连接符（U+200C `‌`）的独占行，格式为：

```
上一段最后一句

‌

下一段第一句
```

3. **不能省略这一步**：如果直接把 vault 原文扔给飞书，所有短句会挤成一坨，没有呼吸感

### 同步流程

```
1. Read 原始 vault 文件
2. 生成飞书版文件（每句双换行 + 零宽字符空段落）
   - 保存为：原文件名-飞书版.md（与原文件同目录）
3. 用 lark-cli 上传到飞书
4. 确认成功后提示用户可删除飞书版临时文件
```

### lark-cli 命令

```bash
# 上传/覆盖飞书文档内容
lark-cli docs +update \
  --doc "飞书文档URL或token" \
  --mode overwrite \
  --markdown "$(cat "飞书版文件路径")"
```

**注意：**
- 如果报 `missing_scope` 错误，需要先授权：`lark-cli auth login --scope "docx:document:write_only"`
- 命令中避免直接内联含引号的长文本（会触发路径检测报错），必须用 `$(cat "文件路径")` 方式传入
- wiki 链接可以直接作为 `--doc` 参数，lark-cli 会自动解析

### 格式转换示例

**Obsidian 原文：**
```
收藏了500条干货。
关注了30个博主。
买了3门课。
手，一下都没动过。

说实话，我手机里的收藏夹比我的行动力丰富多了。
```

**飞书版（转换后）：**
```
收藏了500条干货。

关注了30个博主。

买了3门课。

手，一下都没动过。

‌

说实话，我手机里的收藏夹比我的行动力丰富多了。
```

**规则总结：**
- 组内每句之间：`\n` → `\n\n`（双换行，飞书独立段落）
- 组间空行位置：插入 `‌`（U+200C）独占行，撑出大间距呼吸感
- 标题、加粗行、分割线等 Markdown 语法保持不变

## 检查清单

上传前自检：
- [ ] 每句话之间都是双换行（不存在连续两个非空行紧挨）
- [ ] 原文每个空行位置都有零宽字符 `‌` 独占行
- [ ] 文件用 `$(cat)` 方式传入命令，不内联长文本
- [ ] 飞书链接/token 正确
