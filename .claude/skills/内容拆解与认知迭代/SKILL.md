# 内容拆解与认知迭代

> 从别人的内容里挖金子，和自己的认知碰一碰，该吸收的吸收，该修正的修正。

## 🎯 功能概述

核心解决一个问题：**看了好内容，怎么真正变成自己的认知资产？**

不是做笔记摘抄，而是：
1. **拆解提炼**：这篇内容的核心观点是什么？哪些对我有用？能落地的行动项是什么？
2. **认知碰撞**：和我已有的认知对比——哪些是增量？哪些验证了我的判断？哪些在挑战我的假设？

```
别人的内容 → 核心观点提取 → 与我的认知基线碰撞 → 增量/验证/挑战 → 行动项 → 归档
```

**与其他skill的区别：**

| Skill | 输入 | 核心动作 | 输出 |
|-------|------|---------|------|
| 战略思考迭代 | 自己的交流/思考 | 结构化归档 | 独立笔记+经验沉淀+CLAUDE.md |
| 爆款拆解改写 | 别人的爆款文案 | 拆骨架→改写 | 自己的新文案 |
| **内容拆解与认知迭代** | **别人的任何优质内容** | **提炼→碰撞→吸收** | **认知增量报告+行动项** |

## 📥 输入参数

| 参数 | 必填 | 说明 | 默认值 |
|------|------|------|--------|
| `内容` | ✅ 是 | 别人的内容全文（或vault中已保存的文件路径） | - |
| `作者` | ❌ 否 | 内容作者 | 从内容中提取 |
| `来源` | ❌ 否 | 来源平台/场景 | 从上下文推断 |

## 📚 必读上下文

执行前**必须先读取** `CLAUDE.md`，获取用户信息。然后读取以下文件，建立认知基线：

| 文件 | 路径 | 用途 |
|------|------|------|
| CLAUDE.md | `CLAUDE.md` | 了解用户的业务现状、战略方向、核心认知 |
| 战略相关 | `01.我的战略/决策复盘/` | 了解当前战略框架 |
| 经验沉淀 | `01.我的战略/经验沉淀.md` | 了解已有认知积累 |

> 如果战略目录或经验沉淀为空，跳过对应读取，但提醒用户补充。

## 🔄 工作流程

### Step 1：读取认知基线

读取上面三个文件，建立"我现在知道什么、相信什么、在做什么"的基线。

重点关注：
- 当前战略架构和各层状态
- 当前核心执行项
- 已有的核心认知和经验教训
- 已否决的方向和否决理由

### Step 2：通读原始内容，提取核心观点

完整读取内容，提取：

**观点层：**
- 作者的核心主张是什么？（用一句话概括）
- 支撑论据有哪些？（数据、案例、逻辑链）
- 作者的身份/立场/利益相关？（判断观点的偏向性）

**策略层：**
- 作者提到了哪些具体策略/方法/打法？
- 有没有可验证的数据或案例支撑？

**趋势层：**
- 反映了什么行业趋势或市场信号？
- 这个趋势对我的赛道有什么影响？

### Step 3：认知碰撞

把提取的观点逐条和我的认知基线对比，分三类：

**🆕 增量认知（我不知道的）：**
- 全新的视角、方法、数据
- 我的认知盲区

**✅ 验证认知（我已经知道/在做的，被外部验证了）：**
- 别人的经验证实了我的判断
- 增强信心，值得记录"又一个数据点"

**⚡ 挑战认知（和我现有判断冲突或有张力的）：**
- 不一定是我错了，但值得重新审视
- 标注冲突点，给出"我该怎么看待这个冲突"的建议

### Step 4：提炼行动项

基于碰撞结果，提炼可落地的行动项：

- **立即可做的**（今天/本周就能执行）
- **需要验证的**（先小范围试，再决定是否全面采纳）
- **存入备忘的**（当前不急，但未来可能用到）

每个行动项要具体到"做什么"，不要停留在"关注一下"这种废话层面。

### Step 5：输出认知增量报告

直接在对话中输出，不创建新文件（除非用户要求保存）。

**输出格式：**

```markdown
## 📖 内容拆解：{内容标题/主题}

> 作者：{作者} | 来源：{来源} | 日期：{日期}

### 一句话总结

{作者核心主张，一句话}

### 核心观点提取

1. **{观点1}**：{展开说明}
2. **{观点2}**：{展开说明}
...

### 🧠 认知碰撞

#### 🆕 增量认知（我不知道的）
- {增量1}：{为什么这对我有价值}
- ...

#### ✅ 验证认知（印证了我的判断）
- {验证1}：我的原有判断是「{原判断}」，这篇内容提供了新的佐证——{佐证内容}
- ...

#### ⚡ 挑战认知（值得重新审视的）
- {挑战1}：我原来认为「{原判断}」，但这篇提出「{新观点}」，冲突点在于{分析}。我的建议：{该怎么看}
- ...

### 🎯 行动项

**立即可做：**
- [ ] {具体行动1}
- [ ] {具体行动2}

**需要验证：**
- [ ] {验证项1}——验证方式：{怎么验证}

**存入备忘：**
- {备忘项1}——未来{什么场景}下可能用到
```

### Step 6：询问是否归档

输出报告后，问用户：

> 要不要把认知增量更新到经验沉淀或CLAUDE.md？

如果用户说要：
- **增量认知中特别重要的** → 追加到 `经验沉淀-赛道决策思考.md` 的相关条目下，或新建条目
- **挑战认知导致判断修正的** → 更新 CLAUDE.md 中对应的描述
- **行动项** → 提醒用户自己记到待办系统

如果用户说不用 → 结束。

## ⚠️ 注意事项

1. **不吹不黑，实事求是**：不因为别人说得好就全盘接受，也不因为和我现有判断冲突就否定。碰撞的目的是思考，不是站队
2. **区分"对所有人成立"和"对我成立"**：别人的经验在别人的条件下成立，要判断在我的条件（资源、阶段、赛道）下是否适用
3. **不编造碰撞**：如果内容和我的认知没有冲突，就老实说"没有挑战认知的点"，不要硬凹
4. **观点提取要忠于原文**：不曲解作者意思，提取时保留关键原话
5. **行动项要具体**：不要写"关注一下AI趋势"这种废话，要写"本周在小红书发一条AI+虚拟电商的内容测试流量反馈"
6. **判断作者立场**：如果作者有明显的利益相关（比如卖课的人说"知识付费是未来"），要标注出来

## 🚀 如何启动

用户说出以下任一句式即可启动：
- "拆解一下这篇内容"
- "这篇对我有什么启发"
- "帮我吸收一下这个"
- "和我的认知碰一碰"
- "挖掘一下这篇的价值"
- 保存了别人的内容后说"帮我拆解提炼"

直接开始工作，不需要寒暄。

## Init

收到内容后，按 Step 1-6 顺序执行。先读认知基线，再拆内容，最后碰撞输出。不跳步。
