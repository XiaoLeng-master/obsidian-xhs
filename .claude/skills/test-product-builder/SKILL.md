# Test Product Builder

## 目标

带新手学员从“对标/截图/想法”做出一个能直接交付的测试产品：

- 首页
- 答题页
- 结果页
- 测试题目和选项
- 结果分类和结果文案
- 一个可运行的 `index.html`

原则：**少讲理论，直接带着做。每一步只让学员补最少的信息。**

页面默认审美：**简洁、干净、手机端好读**。不要为了“高级感”堆太多渐变、阴影、图标、装饰、卡片和动画；测试品页面优先让用户快速看懂、快速点击、快速出结果。

## 工作方式

按“新手四步法”推进：

1. 收集输入
2. 生成测试内容
3. 生成单文件页面
4. 检查并给交付说明

不要先输出复杂方法论。不要要求学员理解代码。除非用户明确要求，否则不要讲 HTML/CSS/JS 原理。

## 第一步：判断学员给了什么

### A. 学员给了代码
读取代码，提取：页面结构、题目数量、选项数量、结果数量、计分逻辑、视觉风格。生成新页面时要参考对标的整体风格，包括布局、卡片形态、按钮感觉、色彩氛围、动效节奏，但不能像素级复制；必须做颜色、文案、图标、间距或装饰上的变化。然后直接重写内容并生成新页面。

### B. 学员给了截图
根据截图提取能看见的信息：首页、题目页、结果页、题目数量、结果数量、视觉风格。看不清的地方标注“按常见结构补齐”，不要编造对标原文。

### C. 学员只有一个想法
直接按默认规格生成：8 道题、每题 4 个选项、4 个结果、类型制计分、手机端单文件 HTML。

## 第二步：最少追问

只有缺核心信息时才问。最多问 3 个问题：

1. 这个测试主题是什么？
2. 想做几道题？不知道就默认 8 道。
3. 想要什么风格？不知道就默认“简洁小红书轻量风”。

如果用户已经给了主题，不要再问，直接做。

## 第三步：生成测试内容

用这个结构输出：

```markdown
## 测试主题

## 首页
- 标题：
- 按钮：开始测试

## 题目
1. 题目
   - A. 选项
   - B. 选项
   - C. 选项
   - D. 选项

## 结果
### A 型：结果名
- 一句话：
- 你像什么样的人：
- 你的优势：
- 你的提醒：
- 给你的建议：
```

题目要求：用生活场景提问；选项要有区分度；结果要有情绪价值；不要写成严肃心理诊断；不要使用“权威测评、官方认证、准确率 99%”。

## 第四步：生成页面

默认生成一个单文件 `index.html`：

- 手机端优先
- 不依赖外部库
- 首页、答题页、结果页完整
- 页面风格默认简洁：留白充足、颜色不超过 2-3 个主色、卡片层级少、阴影轻、动效少；不要做复杂拟物、过多渐变、过多 emoji、过重边框
- 首页只保留必要信息：测试标题、1 句说明、开始按钮；如果需要展示题目数/结果数，也要轻量展示
- 答题页重点突出题目和选项，避免无关装饰抢注意力
- 结果页要清晰分块，但不要堆太多模块；优先展示结果名、一句话、解读、建议、重新测试
- 一题一页
- 点击选项自动下一题
- 答完后展示结果
- 支持重新测试
- 代码里用注释标出：在哪里改标题、题目、结果、颜色
- 不允许有代码级错误：按钮点击、题目渲染、选项计分、结果展示必须能正常运行
- **JS 字符串引号安全**：题目和结果文案中如果包含中文引号 `"` `"`、英文引号 `"` `'`、反引号等，必须用 Unicode 转义（`\u201C` `\u201D`）或切换外层引号类型，绝对不能让文案内容的引号与 JS 字符串定界符冲突

如需创建文件，用户未指定目录时放到 `05.我的产品/虚拟产品/测试品/案例产出/`。写文件前必须用 Glob / Get-ChildItem 确认目录；目录不存在就自动创建。

## 第五步：防侵权改写规则

基于对标开发时必须执行：

- 页面结构可以参考
- 题目数量可以参考
- 测试逻辑可以参考
- 代码结构可以复用
- 文案、题目、结果名称、结果解释必须重写
- 图片、logo、品牌名不能照搬
- 颜色、按钮、卡片样式至少做轻微变化
- 即使参考对标的视觉风格，也要主动做“减法”：减少装饰、减少复杂动效、减少花哨模块，让页面更像一个轻量可交付测试品
- 如果用户给的是对标代码，要参考对标的视觉风格和交互节奏，但必须改成相似不相同

提醒用户：这是“结构参考 + 内容重写”，不是像素级复制。

## 第六步：交付检查

交付前检查：

- 首页能打开
- 开始按钮能点击，不能出现点击没反应
- JavaScript 不能有语法错误或初始化错误
- questions / results / scores 这类核心数据结构必须完整匹配，不能出现某一题缺少类型映射导致页面报错
- 每道题能选择
- 答完能出结果
- 结果函数能正确读取结果文案，不能出现 undefined、空白结果或模板变量丢失
- 不同答案能出不同结果
- 手机端能看
- 没有对标原文案
- 结果页不是空话

### 引号冲突检查（必须执行）

JS 字符串使用双引号 `”` 时，中文引号 `”` `”` 会被解析器当作字符串结束符，导致整个 `<script>` 块解析失败，所有函数都不会加载，按钮点击无反应。这是最常见的致命 bug。

生成 HTML 后必须逐条检查：

1. **中文引号冲突**：所有 JS 字符串中的 `”` `”` 必须转义为 `\u201C` `\u201D`，或改用单引号包裹字符串
2. **中文单引号冲突**：如果 JS 字符串用单引号包裹，检查内容中的 `'` `'` 是否冲突
3. **其他特殊字符**：检查文案中是否包含反斜杠 `\`、反引号 `` ` `` 等可能破坏字符串的字符
4. **嵌套引号通用规则**：如果文案内容包含任何引号类符号（中英文引号、书名号等），一律使用 Unicode 转义或确保与外层引号不冲突

快速自检方法：在生成的 HTML 中搜索所有 `text: “` 开头的行，逐行确认引号闭合正确。

### 代码级验证

如果环境允许，写完 HTML 后要做一次代码级验证：

- 对内联 `<script>` 做语法检查，例如提取 JS 后运行 `node --check`
- 或至少人工检查浏览器会执行到的函数：`startTest`、`renderQ/showQuestion`、`choose`、`renderR/showResult`
- 重点检查”开始测试”按钮绑定的函数是否存在，点击后是否能进入第一题

## 第七步：发布上线引导

交付检查通过后，必须引导学员把页面发布成可访问的链接。这一步才算真正闭环。

用以下话术引导（直接发给学员）：

```markdown
页面做好了，最后一步：把它变成一个可以分享的链接。

**操作步骤（3分钟搞定）：**

1. 我把完整的 HTML 代码发给你，全选复制
2. 打开 https://html2web.com/
3. 点击右上角「登录/注册」，微信扫码登录（第一次需要，之后就不用了）
4. 把代码粘贴到输入框，点击「发送」
5. 等几秒钟，页面会出现「预览」和「发布」两个按钮
6. 先点「预览」，检查一遍：
   - 开始按钮能点吗？
   - 8道题都能正常选吗？
   - 最后能出结果吗？
   - 重新测试能回到首页吗？
7. 预览没问题，点「发布」
8. 发布成功后点「分享」，就能拿到你的产品链接了

**拿到链接后你可以：**
- 挂到小红书商品详情页，客户付款后自动发链接
- 发到微信/群里让朋友先测试，帮你传播
- 做成二维码贴在图片上
```

然后把完整的 HTML 源码直接输出给学员（不是文件路径，是代码本身），让学员能直接复制粘贴。

**注意：**
- 如果学员不熟悉 html2web.com，可以推荐备选方案：https://tiiny.host/（也是粘贴 HTML 生成链接）
- 不要让学员自己去文件夹找代码——直接把代码贴出来，降低操作门槛
- 学员确认链接能正常访问后，这个 skill 的任务才算完成
